# 分享連結展開成多個檔案（百度多檔案／資料夾分享）

狀態：草稿（2026-11-17），待使用者確認「待決定」各項後實作。

## 問題

一個百度分享連結可以裝多個檔案或整個資料夾，現在的模組只回傳一個 `Resolved`，遇到多檔就失敗（`only single-file shares are supported`）。

不能在下載開始時才把一個任務拆成多個：任務的 `url` 在**每次傳輸前**都會重新解析（`zoo-core::resolve`，連結過期時也靠它），所以每個任務的 `url` 本身必須能解析成**唯一一個**檔案。

## 做法

在**加入任務之前**展開：模組多一個選用的 `list(url)`，回傳分享裡的每個檔案，每個檔案帶一個「只指向它」的網址。之後每個檔案就是一個普通任務，下載、續傳、過期重新解析都不用改。

```
貼上分享連結 ─▶ 新增視窗 ─▶ list(url) ─▶ 1 個：照舊一列
                                     └▶ N 個：展開成一組可勾選的列 ─▶ 每個勾選的檔案 = 一個任務
任務開始／連結過期 ─▶ resolve(檔案網址) ─▶ 只處理那一個檔案（現有流程）
```

### 1. SDK（`zoo-module.d.ts`，apiVersion 仍為 1，向下相容）

```ts
export interface Listed {
  /** 這個檔案自己的網址：必須符合本模組的 urlPatterns，resolve 收到它只處理這個檔案。 */
  url: string;
  filename: string;
  size?: number;
  /** 在分享裡的資料夾（`a/b`，最上層為空），用來在下載資料夾下重建結構。 */
  folder?: string;
}

export interface SiteModule {
  resolve(url, zoo): Resolved | Promise<Resolved>;
  /** 選用。網址可能含多個檔案時實作；回傳空陣列表示「沒有檔案」，不實作等於只有一個。 */
  list?(url: string, zoo: Zoo): Listed[] | Promise<Listed[]>;
}
```

- host 驗證：每個 `url` 必須是 http(s)、符合模組的 `urlPatterns`／`urlRegex`；`filename`、`folder` 的每一段經過與檔名相同的 sanitize，拒絕 `..`、絕對路徑；最多 **1000** 個（超過就失敗並提示，見待決定 2）。
- 與 `resolve` 同樣的限制（30 秒、128 MB、網域白名單、帳密佔位）。
- `AGENTS.md`、`globals`/型別測試、`sdk.rs` 一致性測試同步更新；`defineModule` 的型別也檢查 `list` 的回傳欄位。

### 2. 協定與 host（zoo-module、zoo-module-client）

- `Request::List { id, module, url, limits }` → 回應 `Listed { id, items }`，失敗沿用 `Failed`。
- 模組沒有 `list` 時回 `Listed` 一個項目（原網址、檔名未知），呼叫端不必區分「不支援」與「只有一個」。
- `zoo-module test`：`tests/cases.json` 的 case 可寫 `"list": true`，`expect` 改成 `{ "count": N, "items": [{ "filename": "...", "folder": "..." }] }`（`*` 萬用字元同現在）。錄製／重播同 resolve。

### 3. App

- 新命令 `urls_list(url) -> Vec<ListedItem>`（`ListedItem` 由 ts-rs 產生，camelCase）。沒有對應模組時回傳一個項目（原網址）。
- `downloads.add` 不變；資料夾結構由前端把 `folder` 接到所選下載資料夾後送出的 `dir` 表達（後端再 sanitize 一次並建立資料夾）。

### 4. 新增視窗

- 由模組處理的列，在 `urls.inspect` 之後呼叫 `urls.list`；期間該列顯示「讀取分享內容…」。
- 結果 1 個：列不變（網址維持原分享網址，與現在相同）。
- 結果 N 個：該列換成一組：
  - 組標題：分享網址、`N 個檔案 · 總大小`、全選勾選框、收合。
  - 每個檔案一列：勾選框（預設全選）、檔名（可改）、大小、所在資料夾。
  - 分類規則逐檔套用（`categories.match(檔案網址, 檔名)`）。
- 「保留資料夾結構」開關（預設開，見待決定 1）：開時任務 `dir` = 下載資料夾 / `folder`。
- `list` 失敗（提取碼錯、未登入…）：該列顯示錯誤，與現在 `add` 失敗的顯示相同，可移除或修正網址重試。
- 送出：只送勾選的檔案；每個一個任務。

### 5. 自動開始（剪貼簿、瀏覽器擴充）

`starts_at_once` 為真時，先 `list`：1 個照舊直接開始；N 個就放進新增視窗（`Pending`）讓使用者挑選，不直接開始 N 個下載。`list` 失敗也送進新增視窗顯示錯誤。

### 6. 百度模組

- 檔案網址：`https://pan.baidu.com/s/1<surl>?pwd=<碼>#path=<分享內路徑，URL 編碼>`。用 fragment：不會送到伺服器、使用者看得懂、跨次呼叫穩定（`fs_id` 也穩定，但得先列目錄才知道，路徑一樣要列目錄）。
- `list`：驗證提取碼 → `share/list` 根目錄 → 對每個資料夾遞迴列出（每頁 100 筆，翻頁到底）。回傳的 `folder` 以分享根為起點。
- `resolve`：有 `#path=` 時列出其上層目錄找到該檔，沒有時沿用「單一檔案」的現有行為；多檔且無 `#path=` 時錯誤改為提示「從新增視窗加入以選擇檔案」。
- 轉存、清理、`locatedownload` 不變：每個檔案在**自己的任務開始時**才轉存（網盤只需容納同時下載的檔案，8 小時後清掉）。
- 已知風險：每個檔案解析要約 6 個請求，大量檔案同時開始可能觸發百度驗證碼（-62）。同時下載數由現有的佇列設定限制；實測若常觸發，再加模組層的節流。
- manifest 描述改成支援多檔與資料夾；`version` 1.1.0。

## 測試

- zoo-module：`list` 的驗證（不符 urlPatterns、`..`、超過上限、缺 `list` 時的預設）、協定往返。
- `sdk.rs` / `module-sdk.test.ts`：`list` 型別、錯誤欄位被標錯。
- 百度：錄製「多檔案」「含子資料夾」兩個分享的 `list` 與其中一個檔案的 `resolve`；現有單檔 case 照常通過。
- 前端：新增視窗展開、勾選、資料夾結構組 `dir`、自動開始遇到多檔時進新增視窗。
- 實機：多檔分享全選下載、只勾部分、子資料夾結構正確、連結過期後單檔重新解析。

## 待決定

1. **資料夾結構**：預設保留（任務放進 `下載資料夾/分享內資料夾`），還是預設全部平放？
2. **上限**：一次最多展開 1000 個檔案，超過就失敗並請使用者分批分享，可以嗎？
3. **測試用分享**：需要你提供一個自己的多檔分享（最好含一層子資料夾、檔案小），用來錄製測試資料。錄製檔不含帳號資料。
4. **自動開始**：多檔分享從剪貼簿或擴充進來時，一律開新增視窗讓你挑（上面的設計），還是全部直接開始？
