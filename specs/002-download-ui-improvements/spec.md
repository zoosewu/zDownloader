# Feature Specification: Download UI Improvements

**Feature Branch**: `002-download-ui-improvements`
**Created**: 2025-12-01
**Status**: Draft
**Input**: User description: "接下來我要做一些改動：
1. 主畫面預設只會顯示下載列表，新增下載的地方會在右上角有一個按鈕點擊使用，新增完之後會自動跳回下載列表的畫面。
2. 偵測到剪貼簿有下載連結的時候自動跳到下載的地方並貼上網址。
偵測下載的時候要分為兩種模式, 1. 檔案帶有附檔名。2. 模組支援的網站能夠客製化該網站下載連結的判斷邏輯。
3. 新下載的地方要提供 path 讓使用者可以調整，並且一開始會放上預設資料夾路徑。"

## User Scenarios & Testing

### User Story 1 - Quick Add Download from Clipboard (Priority: P1)

使用者複製下載連結後,應用程式能自動偵測並快速引導使用者完成下載設定,無需手動貼上網址。

**Why this priority**: 這是最核心的使用者體驗改進,大幅減少添加下載的步驟和時間,是使用者最頻繁執行的操作。

**Independent Test**: 可以通過複製任何有效的下載連結(包含附檔名的直接檔案連結或支援網站的連結),驗證應用程式是否自動開啟新增下載介面並預填網址。

**Acceptance Scenarios**:

1. **Given** 使用者複製了一個包含附檔名的直接檔案連結(如 `https://example.com/file.zip`), **When** 剪貼簿監控偵測到此連結, **Then** 應用程式自動切換到新增下載頁面並將網址預填入輸入框
2. **Given** 使用者複製了支援網站的下載連結(如某個特定網站的檔案頁面), **When** 模組辨識出此為可下載連結, **Then** 應用程式自動切換到新增下載頁面並預填網址
3. **Given** 使用者複製了非下載連結的一般網址, **When** 剪貼簿監控檢查此連結, **Then** 應用程式不做任何反應,保持在當前頁面

---

### User Story 2 - Streamlined Add Download Flow (Priority: P1)

使用者可以通過右上角按鈕快速進入新增下載介面,完成設定後自動返回下載列表,整個流程簡潔流暢。

**Why this priority**: 改善核心工作流程,使主畫面更簡潔專注於下載列表,同時提供清晰的新增下載入口。

**Independent Test**: 可以通過點擊新增按鈕、填寫下載資訊、提交後驗證是否返回下載列表並顯示新任務來獨立測試。

**Acceptance Scenarios**:

1. **Given** 使用者在主畫面(下載列表頁), **When** 點擊右上角的新增下載按鈕, **Then** 頁面切換到新增下載表單
2. **Given** 使用者在新增下載表單填寫完所有必要資訊(網址、可選的檔案名稱和路徑), **When** 點擊確認新增, **Then** 下載任務被建立且頁面自動切換回下載列表
3. **Given** 使用者在新增下載表單, **When** 點擊取消或返回按鈕, **Then** 頁面切換回下載列表且不建立任務

---

### User Story 3 - Customizable Download Path (Priority: P2)

使用者在新增下載時可以自訂儲存路徑,系統預設顯示設定中的預設下載資料夾,方便使用者快速調整。

**Why this priority**: 提供彈性讓使用者組織檔案,雖然重要但可以在基本新增流程之後再實作。

**Independent Test**: 可以通過新增下載時修改路徑欄位,驗證檔案是否下載到指定位置來獨立測試。

**Acceptance Scenarios**:

1. **Given** 使用者開啟新增下載表單, **When** 檢視路徑欄位, **Then** 欄位顯示使用者設定中的預設下載資料夾路徑
2. **Given** 使用者在新增下載表單, **When** 點擊路徑欄位旁的瀏覽按鈕, **Then** 開啟資料夾選擇對話框供使用者選擇新路徑
3. **Given** 使用者手動輸入或選擇了自訂路徑, **When** 提交新增下載, **Then** 檔案下載到指定的自訂路徑而非預設路徑

---

### User Story 4 - Intelligent URL Detection (Priority: P2)

系統能智慧辨識不同類型的下載連結,包括直接檔案連結和特定網站的客製化連結格式。

**Why this priority**: 提升自動化程度和使用者體驗,但依賴於模組系統的完善程度,可以先實作基本的附檔名檢測。

**Independent Test**: 可以分別測試不同格式的連結(直接檔案、各種支援網站),驗證系統是否正確辨識來獨立測試。

**Acceptance Scenarios**:

1. **Given** 系統收到一個包含常見附檔名的連結(如 `.zip`, `.pdf`, `.exe`, `.mp4`), **When** 執行 URL 檢測, **Then** 辨識為可下載的直接檔案連結
2. **Given** 系統收到一個支援網站的連結且已載入對應模組, **When** 模組執行客製化檢測邏輯, **Then** 辨識為該網站的可下載連結
3. **Given** 系統收到一個一般網頁連結(無附檔名且無對應模組), **When** 執行 URL 檢測, **Then** 辨識為非下載連結

---

### Edge Cases

- 當使用者快速連續複製多個下載連結時,系統如何處理?是只處理最新的還是依序提示?
- 當剪貼簿包含非文字內容時,系統如何避免錯誤處理?
- 當使用者選擇的自訂路徑不存在或無寫入權限時,系統如何回應?
- 當使用者在新增下載表單填寫時,剪貼簿又偵測到新的下載連結,是否覆蓋當前輸入?
- 當網址非常長時,新增下載表單的 UI 如何優雅地顯示?

## Requirements

### Functional Requirements

- **FR-001**: 主畫面預設 MUST 顯示下載列表,不包含新增下載表單
- **FR-002**: 主畫面右上角 MUST 提供新增下載的按鈕
- **FR-003**: 點擊新增下載按鈕時,MUST 切換到新增下載介面/頁面
- **FR-004**: 新增下載表單 MUST 包含網址輸入欄位、可選的檔案名稱欄位、下載路徑欄位
- **FR-005**: 下載路徑欄位 MUST 預設顯示使用者設定中的預設下載資料夾
- **FR-006**: 下載路徑欄位 MUST 提供瀏覽按鈕開啟資料夾選擇器
- **FR-007**: 成功提交新增下載表單後,MUST 自動切換回下載列表頁面
- **FR-008**: 系統 MUST 持續監控剪貼簿內容變化(基於使用者設定啟用剪貼簿監控功能)
- **FR-009**: 剪貼簿監控 MUST 能偵測包含常見附檔名的直接檔案連結
- **FR-010**: 偵測到有效下載連結時,MUST 自動切換到新增下載頁面
- **FR-011**: 自動切換到新增下載頁面時,MUST 將偵測到的連結預填入網址欄位
- **FR-012**: 系統 MUST 支援模組化的 URL 檢測機制,允許特定網站模組提供客製化辨識邏輯
- **FR-013**: URL 檢測 MUST 區分兩種模式:直接檔案連結檢測(基於附檔名)和模組客製化檢測
- **FR-014**: 系統 MUST 提供取消/返回功能,讓使用者可以從新增下載頁面返回下載列表
- **FR-015**: 剪貼簿偵測到的連結 MUST 經過驗證(確認為有效 URL 格式)才進行後續處理

### Key Entities

- **Download Task**: 下載任務,包含 URL、檔案名稱、儲存路徑、下載狀態等屬性
- **URL Detection Module**: URL 檢測模組,提供客製化的連結辨識邏輯,可針對特定網站實作
- **Clipboard Monitor**: 剪貼簿監控器,負責監聽剪貼簿變化並觸發 URL 檢測

## Success Criteria

### Measurable Outcomes

- **SC-001**: 使用者從複製連結到開始下載的操作步驟減少至 2 步(自動跳轉並預填後只需確認路徑和提交)
- **SC-002**: 90% 的使用者能在首次嘗試時成功通過新增下載流程建立下載任務
- **SC-003**: 剪貼簿監控的偵測延遲時間在 500 毫秒內完成
- **SC-004**: 常見附檔名的直接檔案連結偵測準確率達 95% 以上
- **SC-005**: 使用者可在 5 秒內完成從主畫面進入新增下載、填寫資訊到返回列表的完整流程

## Scope

### In Scope

- 重新設計主畫面為下載列表專用
- 新增獨立的新增下載介面/頁面
- 實作剪貼簿監控和自動跳轉功能
- 支援基於附檔名的直接檔案連結檢測
- 提供模組化介面供特定網站客製化 URL 檢測邏輯
- 自訂下載路徑功能與預設路徑預填

### Out of Scope

- 實作具體網站的 URL 檢測模組(僅提供模組化介面)
- 批次新增多個下載
- 下載任務的進階排程或優先級設定
- 剪貼簿監控的詳細設定(如檢測間隔、黑名單等)

## Assumptions

- 使用者已在設定中啟用剪貼簿監控功能
- 系統已實作基本的檔案系統權限檢查機制
- UI 框架支援頁面/檢視切換功能
- 現有程式碼已有設定管理功能,可儲存和讀取預設下載路徑
- 常見附檔名列表已在系統中定義(如 `.zip`, `.pdf`, `.exe`, `.mp4`, `.mkv`, `.rar`, `.7z`, `.tar`, `.gz`, `.iso`, `.dmg`, `.apk`)

## Dependencies

- 現有的剪貼簿監控功能實作
- 設定管理系統(讀取預設下載路徑)
- 檔案系統存取權限
- UI 路由或頁面切換機制

## Constraints

- 剪貼簿監控功能需要使用者明確授予權限
- 不同作業系統的剪貼簿 API 可能有差異,需跨平台相容性考量
- URL 檢測邏輯需要足夠快速,避免影響使用者體驗
