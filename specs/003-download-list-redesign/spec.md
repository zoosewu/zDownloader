# Feature Specification: 下載列表 UI 重新設計

**Feature Branch**: `003-download-list-redesign`
**Created**: 2025-12-03
**Status**: Draft
**Input**: User description: "下載列表 UI 重新設計 - 改用表格視圖顯示下載項目，並在下方提供詳細信息面板，使用固定大小的彩色方格來視覺化下載分段狀態"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 表格視圖查看所有下載項目 (Priority: P1)

用戶打開下載列表時，可以在一個表格中看到所有下載項目的關鍵資訊，包括檔案名稱、大小、進度、速度、狀態、建立時間和預估剩餘時間。每個下載項目佔用一行，資訊清晰易讀。

**Why this priority**: 這是最核心的功能，提供下載項目的總覽視圖。沒有這個基礎，後續的詳細信息和視覺化功能都無法實現。這個功能本身就能為用戶帶來價值，讓他們快速了解所有下載的狀態。

**Independent Test**: 可以通過打開下載列表頁面並驗證所有下載項目是否以表格形式正確顯示來獨立測試。不需要依賴其他功能。

**Acceptance Scenarios**:

1. **Given** 系統中有 5 個下載項目（包含不同狀態：下載中、已完成、失敗），**When** 用戶打開下載列表頁面，**Then** 應該看到一個包含 5 行的表格，每行顯示一個下載項目的檔名、大小、進度、速度、狀態、建立時間和剩餘時間
2. **Given** 用戶正在查看下載列表，**When** 有一個下載項目正在進行中，**Then** 該項目的進度、速度和剩餘時間應該實時更新
3. **Given** 系統中沒有任何下載項目，**When** 用戶打開下載列表頁面，**Then** 應該看到一個空的表格並顯示提示訊息「目前沒有下載項目」

---

### User Story 2 - 選擇項目並查看詳細信息 (Priority: P2)

用戶可以點擊表格中的任何下載項目，該項目會被高亮顯示，同時在表格下方的滿版詳細信息面板中顯示該項目的完整資訊。詳細面板使用 Tab 切換不同類型的信息，包括：基本信息、分段視覺化、錯誤信息（如果有）和進階資訊。

**Why this priority**: 這是第二重要的功能，建立在 P1 的基礎上。當用戶需要深入了解某個下載的詳細狀態時，這個功能提供了必要的資訊。可以獨立於分段視覺化實現。

**Independent Test**: 可以通過點擊表格中的項目並驗證選中狀態和詳細面板顯示來獨立測試。即使分段視覺化尚未實現，基本信息、錯誤信息和進階資訊的 Tab 仍然可以正常工作。

**Acceptance Scenarios**:

1. **Given** 下載列表中有多個項目，**When** 用戶點擊其中一個項目，**Then** 該項目應該被高亮顯示，且下方詳細面板應該顯示該項目的基本信息
2. **Given** 用戶已選中一個下載項目，**When** 用戶點擊詳細面板中的不同 Tab（基本信息、分段視覺化、錯誤信息、進階資訊），**Then** 應該切換顯示對應的內容
3. **Given** 用戶已選中一個失敗的下載項目，**When** 用戶切換到錯誤信息 Tab，**Then** 應該看到該下載失敗的詳細錯誤訊息
4. **Given** 用戶已選中一個項目，**When** 用戶點擊另一個項目，**Then** 新項目應該被高亮，詳細面板應該切換到新項目的信息
5. **Given** 用戶已選中一個項目並查看詳細信息，**When** 該項目被從系統中刪除，**Then** 詳細面板應該清空或顯示提示訊息「請選擇一個下載項目」

---

### User Story 3 - 分段視覺化 (Priority: P3)

用戶可以在詳細面板的「分段視覺化」Tab 中看到當前選中下載項目的所有分段，以固定大小的小方格形式顯示。每個方格代表一個分段，顏色反映其狀態：灰色表示待處理、藍色表示下載中、綠色表示完成、紅色表示失敗。用戶將滑鼠懸停在方格上時，可以看到該分段的詳細信息。

**Why this priority**: 這是進階功能，幫助用戶深入了解下載的內部進度細節。雖然有價值，但不是完成基本下載管理任務的必需功能。可以在 P1 和 P2 完成後獨立添加。

**Independent Test**: 可以通過選擇一個有多個分段的下載項目，切換到分段視覺化 Tab，並驗證方格顯示和懸停信息來獨立測試。

**Acceptance Scenarios**:

1. **Given** 用戶選中了一個有 10 個分段的下載項目，**When** 用戶切換到分段視覺化 Tab，**Then** 應該看到 10 個固定大小的方格，每個方格的顏色對應其分段狀態
2. **Given** 用戶正在查看分段視覺化，**When** 用戶將滑鼠懸停在一個方格上，**Then** 應該顯示該分段的詳細信息工具提示，包含：分段 ID、大小範圍、已下載大小、進度百分比、狀態、重試次數、使用的代理（如果有）
3. **Given** 用戶正在查看一個下載中項目的分段視覺化，**When** 某個分段的狀態從「下載中」變為「完成」，**Then** 該方格的顏色應該從藍色變為綠色
4. **Given** 用戶選中了一個有 1000 個分段的下載項目，**When** 用戶切換到分段視覺化 Tab，**Then** 應該能流暢地顯示所有方格（可能需要滾動），且懸停響應迅速

---

### Edge Cases

- **沒有下載項目**：當系統中沒有任何下載項目時，表格應該顯示空狀態並提示用戶「目前沒有下載項目，請點擊新增按鈕開始下載」
- **下載速度為零**：當下載暫停或網速極慢導致當前速度為 0 時，剩餘時間應該顯示「--」或「計算中」，而不是無限大或錯誤值
- **大量分段**：當下載項目有超過 1000 個分段時，分段視覺化應該能夠正常顯示並保持流暢的互動性能。可能需要虛擬化滾動或分頁顯示
- **選中項目被刪除**：當用戶正在查看某個項目的詳細信息，但該項目被刪除（可能通過其他操作或自動清理），詳細面板應該自動清空並顯示提示「所選項目已被移除」
- **極長檔案名稱**：當檔案名稱很長時，表格中應該截斷並顯示省略號，完整檔名可以通過懸停工具提示查看
- **未開始的下載**：當下載項目已創建但尚未開始時，進度應該顯示 0%，速度應該顯示「--」，剩餘時間應該顯示「等待中」
- **錯誤信息為空**：當下載項目狀態為失敗但沒有錯誤信息時，錯誤信息 Tab 應該顯示「無詳細錯誤信息」
- **時間顯示**：建立時間應該使用友好的相對時間格式（例如「5 分鐘前」、「昨天」），但懸停時顯示完整的絕對時間

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系統必須以表格形式顯示所有下載項目，每個項目佔用一行
- **FR-002**: 表格必須包含以下欄位：檔案名稱、檔案大小、下載進度（百分比）、當前速度、狀態、建立時間、剩餘時間
- **FR-003**: 剩餘時間必須根據公式計算：剩餘容量（remaining_size）/ 當前下載速度（current_speed）
- **FR-004**: 用戶必須能夠點擊表格中的任何項目以選中它
- **FR-005**: 系統必須高亮顯示當前選中的項目，使其視覺上與其他項目區分開來
- **FR-006**: 系統必須在表格下方顯示滿版的詳細信息面板
- **FR-007**: 詳細信息面板必須顯示當前選中項目的完整資訊
- **FR-008**: 詳細信息面板必須使用 Tab 切換介面，包含四個 Tab：基本信息、分段視覺化、錯誤信息、進階資訊
- **FR-009**: 基本信息 Tab 必須顯示：URL、檔案路徑、檔案大小、建立時間、開始時間、完成時間（如果已完成）
- **FR-010**: 分段視覺化 Tab 必須以固定大小的小方格形式顯示所有分段
- **FR-011**: 每個分段方格必須根據分段狀態使用對應顏色：灰色（Pending）、藍色（Downloading）、綠色（Completed）、紅色（Failed）
- **FR-012**: 用戶將滑鼠懸停在分段方格上時，系統必須顯示該分段的詳細信息，包括：分段 ID、大小範圍（start_byte - end_byte）、已下載大小、進度百分比、狀態、重試次數、使用的代理（如果有）
- **FR-013**: 錯誤信息 Tab 必須顯示下載失敗的詳細錯誤訊息（如果有）
- **FR-014**: 進階資訊 Tab 必須顯示：重試次數、最大重試次數、上次重試時間、排程開始時間（如果有）
- **FR-015**: 系統必須實時更新表格中正在進行的下載項目的進度、速度和剩餘時間
- **FR-016**: 當沒有下載項目時，系統必須顯示空狀態提示訊息
- **FR-017**: 當下載速度為 0 時，剩餘時間必須顯示為「--」或「計算中」
- **FR-018**: 當選中的項目被刪除時，系統必須清空詳細面板並顯示提示訊息

### Key Entities

- **DownloadTask（下載任務）**: 代表一個完整的下載任務。關鍵屬性包括：唯一識別碼、URL、檔案名稱、檔案路徑、檔案大小、下載狀態、進度百分比、當前速度、建立時間、開始時間、完成時間、錯誤訊息、排程時間、重試相關信息。包含多個 DownloadSegment
- **DownloadSegment（下載分段）**: 代表下載任務的一個分段。關鍵屬性包括：分段 ID、起始位元組、結束位元組、已下載位元組、分段狀態、重試次數、使用的代理。屬於一個 DownloadTask
- **SegmentStatus（分段狀態）**: 分段的狀態枚舉，包括：Pending（待處理）、Downloading（下載中）、Completed（完成）、Failed（失敗）

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用戶打開下載列表後，在 1 秒內能看到所有下載項目的表格視圖
- **SC-002**: 用戶點擊一個下載項目後，在 200 毫秒內看到該項目被高亮並在詳細面板中顯示其信息
- **SC-003**: 對於有 100 個分段的下載項目，分段視覺化 Tab 能在 500 毫秒內完成渲染
- **SC-004**: 用戶將滑鼠懸停在分段方格上時，工具提示在 100 毫秒內顯示
- **SC-005**: 剩餘時間估算的誤差在 10% 以內（對於過去 30 秒內速度穩定的下載）
- **SC-006**: 用戶能夠通過新的 UI 在 3 秒內識別出哪些下載有問題（通過查看狀態和分段視覺化）
- **SC-007**: 表格和詳細面板的資訊更新延遲不超過 1 秒（對於正在進行的下載）
- **SC-008**: 新的 UI 能夠流暢顯示和操作至少 1000 個下載項目的列表
- **SC-009**: 用戶在使用新 UI 時，完成「查看特定下載的詳細狀態」任務的時間減少 50%（相比舊 UI）

## Assumptions

- 假設下載任務的資料模型（DownloadTask 和 DownloadSegment）已經存在且包含所有必要的欄位
- 假設系統已經有機制來實時更新下載任務的狀態、進度和速度
- 假設系統能夠提供下載項目列表的訂閱或輪詢機制，以便 UI 能夠實時更新
- 假設分段方格的固定大小約為 10-20 像素，具體尺寸由 UI 設計決定
- 假設大部分下載項目的分段數量在 10-100 個之間，極端情況可能達到 1000 個
- 假設建立時間使用相對時間格式（如「5 分鐘前」）可以提供更好的用戶體驗
- 假設當前 UI 框架（Material-UI）已經提供了表格、Tab 和工具提示等必要的基礎組件

## Out of Scope

- 在表格中排序或篩選下載項目（可以在後續功能中添加）
- 批量操作下載項目（如批量刪除、批量暫停）
- 自定義表格欄位顯示（讓用戶選擇顯示哪些欄位）
- 匯出下載列表或統計資料
- 在分段視覺化中顯示更細緻的動畫效果（如進度條動畫）
- 分段方格的自定義顏色配置
- 深色模式或主題切換（假設在全局層級處理）
- 響應式設計的移動端優化（本規格主要針對桌面端）
