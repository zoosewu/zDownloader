# Feature Specification: Zoo Downloader - 跨平台下載器核心功能

**Feature Branch**: `001-core-downloader`
**Created**: 2025-01-27
**Status**: Draft
**Input**: 建立跨平台 HTTP/HTTPS 下載器，支援多線程分段下載、斷點續傳、Proxy 支援、模組化架構

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 基本下載功能 (Priority: P1)

使用者可以透過貼上 URL 或從剪貼簿自動偵測來下載單一檔案，並即時查看下載進度、控制下載（暫停/繼續/取消）。

**Why this priority**: 這是下載器的核心價值主張。沒有可靠的基本下載功能，其他進階功能都無意義。這是 MVP 的基礎。

**Independent Test**: 使用者貼上一個 HTTP/HTTPS URL，點擊下載按鈕，可以看到下載進度並成功下載檔案。可以在下載過程中暫停、繼續或取消下載。

**Acceptance Scenarios**:

1. **Given** 應用程式已開啟，**When** 使用者貼上有效的 HTTP/HTTPS URL 並點擊下載，**Then** 系統開始下載並顯示即時進度（速度、剩餘時間、百分比）
2. **Given** 檔案正在下載中，**When** 使用者點擊暫停，**Then** 下載暫停且可以稍後繼續
3. **Given** 下載已暫停，**When** 使用者點擊繼續，**Then** 下載從暫停處恢復
4. **Given** 檔案正在下載或已暫停，**When** 使用者點擊取消，**Then** 下載停止且部分檔案被清理
5. **Given** 使用者複製了一個 URL 到剪貼簿，**When** 剪貼簿內容變更，**Then** 系統自動偵測並彈出提示詢問是否要下載
6. **Given** 下載完成，**When** 檔案儲存到指定目錄，**Then** 系統顯示完成通知並記錄到歷史

---

### User Story 2 - 批次下載管理 (Priority: P2)

使用者可以透過匯入文字檔案一次新增多個下載 URL，並透過下載佇列管理多個下載任務。

**Why this priority**: 個人使用者經常需要批次下載多個檔案。這個功能大幅提升效率，是基本下載的自然延伸。

**Independent Test**: 使用者準備一個包含多個 URL 的文字檔（每行一個），匯入後可以看到所有下載任務排隊，並能管理整個佇列。

**Acceptance Scenarios**:

1. **Given** 使用者有一個包含多個 URL 的文字檔（換行分隔），**When** 使用者匯入該檔案，**Then** 所有 URL 被加入下載佇列
2. **Given** 多個下載任務在佇列中，**When** 系統開始下載，**Then** 根據設定的同時下載數量限制依序執行
3. **Given** 下載佇列有多個任務，**When** 使用者調整任務順序或優先級，**Then** 佇列順序更新並反映在執行順序上
4. **Given** 多個下載正在進行，**When** 使用者點擊全部暫停，**Then** 所有正在下載的任務都暫停
5. **Given** 佇列中有已完成、進行中、失敗的任務，**When** 使用者查看佇列，**Then** 可以清楚看到每個任務的狀態並可篩選

---

### User Story 3 - 多線程分段下載與斷點續傳 (Priority: P3)

使用者下載大檔案時，系統自動使用多線程分段下載加速，並在網路中斷後能自動或手動恢復下載而無需重新開始。

**Why this priority**: 這是針對大檔案下載的關鍵優化。使用者選擇專用下載器而非瀏覽器的主要原因之一就是下載速度和可靠性。

**Independent Test**: 使用者下載一個大檔案（例如 5GB），系統自動使用多個線程加速下載。模擬網路中斷後，重新啟動應用程式能恢復下載而不需從頭開始。

**Acceptance Scenarios**:

1. **Given** 使用者開始下載大檔案，**When** 系統偵測檔案支援 Range Request，**Then** 自動分段（預設 10MB 每段）並使用多線程下載
2. **Given** 下載過程中網路中斷，**When** 網路恢復後使用者點擊繼續，**Then** 系統從已下載的位置恢復而非重新開始
3. **Given** 應用程式在下載過程中異常關閉，**When** 使用者重新啟動應用程式，**Then** 系統偵測到未完成的下載並詢問是否恢復
4. **Given** 部分檔案已下載，**When** 系統檢查部分檔案的完整性（容差 ±1 byte），**Then** 有效的分段被保留，損壞的分段被重新下載
5. **Given** 使用者在設定中調整線程數或分段大小，**When** 開始新的下載，**Then** 使用新的設定值

---

### User Story 4 - Proxy 支援與管理 (Priority: P4)

使用者可以配置 HTTP Proxy，系統自動驗證 Proxy 可用性，並在下載時動態分配和輪替 Proxy。

**Why this priority**: 對於需要透過 Proxy 存取資源的使用者（例如跨區域下載），這是必需功能。Proxy 管理的自動化減少手動配置負擔。

**Independent Test**: 使用者從 Proxy list 網站取得 Proxy 列表，匯入後系統自動驗證並使用可用 Proxy 進行下載。當某個 Proxy 失敗時，自動切換到下一個。

**Acceptance Scenarios**:

1. **Given** 使用者輸入 Proxy list（格式：`ip:port`，每行一個），**When** 系統接收列表，**Then** 自動批次驗證（每批 50 個）並標記可用 Proxy
2. **Given** Proxy 驗證完成，**When** 系統儲存結果，**Then** 可用 Proxy 被快取到 `proxies.txt` 供下次使用
3. **Given** 多個可用 Proxy 存在，**When** 開始下載任務，**Then** 系統為不同的下載分段分配不同 Proxy（負載平衡）
4. **Given** 某個 Proxy 在下載過程中失敗，**When** 系統偵測到失敗，**Then** 自動切換到下一個可用 Proxy 並標記失敗的 Proxy
5. **Given** 所有 Proxy 都不可用，**When** 系統嘗試所有 Proxy 後，**Then** 優雅降級使用直接連線（如果使用者允許）
6. **Given** 使用者啟用總下載速度限制，**When** 透過多個 Proxy 下載，**Then** 系統在所有 Proxy 上均勻分配速度限制

---

### User Story 5 - 模組化網站支援 (Priority: P5)

使用者可以輸入特定網站的頁面 URL（非直接下載連結），系統透過網站支援模組自動解析並取得下載連結。

**Why this priority**: 許多檔案分享網站不直接提供下載連結，需要解析頁面、處理 CAPTCHA 等。模組化設計使未來可以輕鬆擴充支援更多網站。

**Independent Test**: 使用者輸入一個檔案分享網站（例如 MediaFire）的頁面 URL，系統使用對應模組解析頁面（可能需要使用者完成 CAPTCHA），並自動開始下載。

**Acceptance Scenarios**:

1. **Given** 使用者輸入支援網站的頁面 URL，**When** 系統偵測到對應的網站模組，**Then** 自動載入模組並開始解析
2. **Given** 網站需要 CAPTCHA 驗證，**When** 系統偵測到 CAPTCHA，**Then** 在 UI 中顯示 CAPTCHA 圖片並等待使用者輸入
3. **Given** 使用者完成 CAPTCHA，**When** 驗證成功，**Then** 系統取得下載連結並開始下載
4. **Given** 網站需要帳號登入，**When** 使用者提供憑證，**Then** 系統安全儲存憑證（加密）並使用憑證存取下載連結
5. **Given** 網站頁面包含動態載入的下載連結（需 JavaScript 執行），**When** 系統使用 headless browser 解析，**Then** 成功取得動態生成的下載連結
6. **Given** 使用者新增自訂網站模組，**When** 模組放置在指定目錄，**Then** 系統自動偵測並載入新模組（執行時動態載入）

---

### User Story 6 - Chrome 瀏覽器整合 (Priority: P6)

使用者在 Chrome 瀏覽器中瀏覽時，擴充套件自動偵測頁面中的下載連結並可直接傳送到下載器。

**Why this priority**: 瀏覽器整合提升使用便利性，讓使用者無需手動複製貼上 URL。這是進階使用者體驗優化。

**Independent Test**: 使用者安裝 Chrome 擴充套件，瀏覽包含下載連結的網頁，擴充套件自動偵測並顯示圖示，點擊後連結傳送到下載器應用程式。

**Acceptance Scenarios**:

1. **Given** Chrome 擴充套件已安裝，**When** 使用者瀏覽包含下載連結的頁面，**Then** 擴充套件偵測到連結並在瀏覽器工具列顯示圖示
2. **Given** 擴充套件偵測到下載連結，**When** 使用者點擊擴充套件圖示，**Then** 連結傳送到下載器應用程式並自動加入下載佇列
3. **Given** 下載器應用程式未執行，**When** 使用者從擴充套件傳送連結，**Then** 系統自動啟動下載器應用程式並加入下載
4. **Given** 使用者在瀏覽器中開始下載，**When** 擴充套件偵測到下載事件，**Then** 可選擇攔截並轉到下載器處理

---

### User Story 7 - 排程與自動化下載 (Priority: P7)

使用者可以設定排程下載任務，在指定時間自動開始下載，並配置自動重試機制。

**Why this priority**: 排程下載讓使用者可以在非尖峰時段（例如深夜）下載大檔案，自動重試減少手動干預。這是便利性優化功能。

**Independent Test**: 使用者設定一個下載任務在晚上 11 點開始，到了時間系統自動開始下載。如果下載失敗，系統按照設定的重試策略自動重試。

**Acceptance Scenarios**:

1. **Given** 使用者新增下載任務並設定排程時間，**When** 到達指定時間，**Then** 系統自動開始下載
2. **Given** 下載過程中發生錯誤，**When** 系統偵測到錯誤，**Then** 根據設定的重試策略（次數、間隔）自動重試
3. **Given** 重試達到最大次數仍失敗，**When** 系統放棄重試，**Then** 標記任務為失敗並通知使用者
4. **Given** 排程下載時應用程式未執行，**When** 到達排程時間，**Then** 系統自動啟動應用程式並執行下載（需要背景服務）
5. **Given** 使用者設定速度限制模式排程，**When** 到達指定時間，**Then** 系統自動切換速度限制模式（例如：白天限速、晚上全速）

---

### User Story 8 - 進階功能（分類、通知、設定） (Priority: P8)

使用者可以透過分類管理下載檔案、接收下載完成通知、自訂應用程式設定（下載目錄、主題、語言等）。

**Why this priority**: 這些功能提升長期使用體驗和個人化，但不是核心下載功能的必需品。適合在核心功能穩定後逐步加入。

**Independent Test**: 使用者下載不同類型的檔案，系統自動分類到不同資料夾。下載完成後收到系統通知。使用者可以在設定中調整語言、主題、預設下載路徑等。

**Acceptance Scenarios**:

1. **Given** 使用者啟用自動分類，**When** 下載檔案完成，**Then** 系統根據檔案類型（影片、音訊、文件、壓縮檔等）自動移動到對應子資料夾
2. **Given** 下載完成，**When** 系統完成檔案儲存，**Then** 發送系統通知告知使用者下載完成
3. **Given** 使用者在設定中切換語言（繁中/英/日），**When** 儲存設定，**Then** 整個 UI 立即切換到選定語言
4. **Given** 使用者切換淺色/深色模式，**When** 儲存設定，**Then** UI 主題立即更新
5. **Given** 使用者設定預設下載目錄，**When** 開始新的下載，**Then** 檔案預設儲存到指定目錄
6. **Given** 使用者需要在不同電腦間同步設定，**When** 匯出設定為 JSON 檔案，**Then** 可以在另一台電腦匯入並恢復所有設定
7. **Given** 應用程式最小化到系統托盤，**When** 下載完成，**Then** 托盤圖示顯示通知並提供快捷操作（開啟下載資料夾、顯示視窗等）

### Edge Cases

- **檔案名稱衝突**: 當下載的檔案名稱與現有檔案衝突時，系統自動在檔名後加上編號（例如：`file.zip` → `file (1).zip`）
- **磁碟空間不足**: 下載前檢查可用空間，如果空間不足則警告使用者並拒絕開始下載
- **網路完全中斷**: 長時間網路中斷後，系統停止當前下載並標記為暫停，等待使用者手動恢復
- **無效或過期的 URL**: 系統偵測到 404 或其他錯誤狀態碼時，標記下載為失敗並記錄錯誤原因
- **Proxy 全部失效**: 當所有 Proxy 都不可用時，系統詢問使用者是否使用直接連線，或停止下載
- **CAPTCHA 驗證失敗**: 使用者輸入錯誤的 CAPTCHA 時，系統自動重新請求新的 CAPTCHA 並允許重試
- **檔案大小與伺服器回應不符**: 下載完成後，如果檔案大小與 Content-Length 不符，標記為失敗並允許重新下載
- **並發下載數過多**: 使用者設定為無限制時，系統根據系統資源（記憶體、網路頻寬）動態調整實際並發數，避免系統過載
- **斷點續傳不支援**: 當伺服器不支援 Range Request 時，系統降級為單線程下載，並在中斷後無法恢復（需要重新開始）
- **模組載入失敗**: 當網站模組損壞或不相容時，系統顯示錯誤訊息並回退到直接使用 URL（如果是直接下載連結）
- **跨平台路徑問題**: 確保 Windows 的 `C:\Users\...` 和 Linux/macOS 的 `/home/...` 路徑都能正確處理
- **特殊字元檔名**: 處理檔名中的特殊字元（例如 `<>:"/\|?*`）在不同作業系統的限制

## Requirements *(mandatory)*

### Functional Requirements

#### 核心下載功能

- **FR-001**: 系統必須支援 HTTP 和 HTTPS 協定的檔案下載
- **FR-002**: 系統必須顯示即時下載進度，包括當前速度（KB/s, MB/s）、已下載大小、總大小、剩餘時間、完成百分比
- **FR-003**: 使用者必須能夠暫停正在進行的下載，並在稍後恢復
- **FR-004**: 使用者必須能夠取消下載，系統必須清理部分下載的檔案（.part 檔案）
- **FR-005**: 系統必須在下載完成時顯示通知（系統原生通知）
- **FR-006**: 系統必須記錄下載歷史，包括 URL、檔名、下載時間、檔案大小、狀態（成功/失敗）

#### 剪貼簿與自動化

- **FR-007**: 系統必須監聽剪貼簿變更，自動偵測 URL 並彈出提示詢問使用者是否下載
- **FR-008**: 系統必須允許使用者啟用/停用剪貼簿監聽功能
- **FR-009**: 系統必須自動重試失敗的下載，重試次數和間隔時間必須可配置

#### 批次下載

- **FR-010**: 使用者必須能夠匯入文字檔案（.txt），系統解析每行作為一個 URL 並加入下載佇列
- **FR-011**: 系統必須支援下載佇列管理，顯示所有待下載、進行中、已完成、失敗的任務
- **FR-012**: 使用者必須能夠調整佇列中任務的順序和優先級
- **FR-013**: 使用者必須能夠設定同時下載的任務數量上限（預設無限制，可自訂）
- **FR-014**: 系統必須支援全部暫停、全部開始、全部取消等批次操作

#### 多線程與分段下載

- **FR-015**: 系統必須支援 HTTP Range Request 進行分段下載
- **FR-016**: 系統必須將檔案分段為固定大小的區塊（預設 10MB，可由使用者調整，最小 5MB）
- **FR-017**: 系統必須使用多線程並行下載不同分段（預設執行緒數可配置）
- **FR-018**: 系統必須在所有分段下載完成後合併成完整檔案
- **FR-019**: 系統必須在下載過程中即時更新總進度（所有分段的綜合進度）

#### 斷點續傳

- **FR-020**: 系統必須儲存未完成下載的分段資訊（已下載的位元組範圍）
- **FR-021**: 系統必須在恢復下載時檢查部分檔案的完整性（檔案大小容差 ±1 byte）
- **FR-022**: 系統必須跳過已完成的分段，僅下載未完成或損壞的分段
- **FR-023**: 系統必須在應用程式重新啟動時自動偵測未完成的下載並詢問使用者是否恢復
- **FR-024**: 系統必須處理伺服器不支援 Range Request 的情況，降級為單線程下載並禁用斷點續傳

#### Proxy 支援

- **FR-025**: 系統必須支援 HTTP Proxy（格式：`ip:port`）
- **FR-026**: 系統必須支援批次驗證 Proxy 列表（每批 50 個，並行驗證）
- **FR-027**: 系統必須測試 Proxy 連線到 `https://api.myip.com` 作為驗證端點，超時時間 5 秒
- **FR-028**: 系統必須將驗證通過的 Proxy 快取到 `proxies.txt` 檔案
- **FR-029**: 系統必須支援動態 Proxy 池管理，為不同下載分段分配不同 Proxy（負載平衡）
- **FR-030**: 系統必須在 Proxy 失敗時自動切換到下一個可用 Proxy
- **FR-031**: 系統必須追蹤 Proxy 的成功率和回應時間，優先使用可靠的 Proxy
- **FR-032**: 系統必須在所有 Proxy 失效時優雅降級到直接連線（需使用者確認）
- **FR-033**: 系統必須支援總下載速度限制（固定限速模式），並在多個 Proxy 間均勻分配限制

#### 模組化網站支援

- **FR-034**: 系統必須支援執行時動態載入網站支援模組（無需重新編譯核心程式）
- **FR-035**: 網站模組必須能夠驗證 URL 是否屬於其支援的網站域名
- **FR-036**: 網站模組必須能夠解析頁面並提取下載連結
- **FR-037**: 網站模組必須能夠處理 CAPTCHA，在 UI 中顯示圖片並接收使用者輸入
- **FR-038**: 網站模組必須支援帳號密碼登入，系統必須加密儲存使用者憑證
- **FR-039**: 網站模組必須能夠執行 JavaScript（整合 headless browser）以處理動態生成的下載連結
- **FR-040**: 網站模組必須支援禮貌性延遲（遵守 API 的 `time_wait` 欄位或速率限制）
- **FR-041**: 系統必須提供模組開發 SDK 和文件，讓開發者可以建立自訂網站支援模組
- **FR-042**: 系統必須在啟動時自動掃描模組目錄並載入所有有效模組
- **FR-043**: 系統必須支援模組版本管理和相容性檢查

#### Proxy List 模組

- **FR-044**: 系統必須支援執行時動態載入 Proxy List 來源模組
- **FR-045**: Proxy List 模組必須能夠從指定網站抓取 Proxy 列表
- **FR-046**: Proxy List 模組必須能夠解析不同格式的 Proxy 資料（JSON、純文字、HTML 表格等）
- **FR-047**: 系統必須自動使用 Proxy List 模組定期更新可用 Proxy 列表

#### Chrome 瀏覽器整合

- **FR-048**: 系統必須提供 Chrome 擴充套件，能夠偵測頁面中的下載連結
- **FR-049**: 擴充套件必須能夠透過 Native Messaging 與 Tauri 應用程式通訊
- **FR-050**: 擴充套件必須在偵測到下載連結時在工具列顯示圖示
- **FR-051**: 使用者必須能夠從擴充套件一鍵傳送下載連結到應用程式
- **FR-052**: 系統必須在應用程式未執行時自動啟動應用程式並接收下載連結

#### 排程與自動化

- **FR-053**: 使用者必須能夠為下載任務設定排程時間（日期和時間）
- **FR-054**: 系統必須在到達排程時間時自動開始下載
- **FR-055**: 系統必須支援速度限制模式排程（例如：白天限速 1MB/s，晚上無限制）
- **FR-056**: 系統必須提供背景服務，即使應用程式關閉也能在排程時間自動執行下載

#### 分類與檔案管理

- **FR-057**: 系統必須支援根據檔案類型自動分類（影片、音訊、文件、壓縮檔、其他）
- **FR-058**: 使用者必須能夠設定預設下載目錄
- **FR-059**: 使用者必須能夠為每個下載任務自訂下載目錄和檔名
- **FR-060**: 系統必須在檔名衝突時自動重命名（加上編號，例如 `file (1).zip`）
- **FR-061**: 系統必須在下載前檢查磁碟可用空間，空間不足時警告使用者

#### UI/UX

- **FR-062**: 系統必須提供簡潔、扁平化的 Material UI 設計
- **FR-063**: 系統必須支援淺色和深色模式切換
- **FR-064**: 系統必須支援多語言（繁體中文、英文、日文），翻譯檔案使用 JSON 格式管理
- **FR-065**: 系統必須根據作業系統語言自動選擇介面語言（可手動覆蓋）
- **FR-066**: 系統必須支援系統托盤最小化，並在托盤提供快捷操作選單
- **FR-067**: 系統必須在下載進行時在托盤圖示顯示進度指示
- **FR-068**: 錯誤訊息必須友善且提供可操作的建議（例如：「網路連線失敗，請檢查網路設定或嘗試使用 Proxy」）

#### 設定管理

- **FR-069**: 使用者必須能夠匯出所有設定為 JSON 檔案
- **FR-070**: 使用者必須能夠匯入 JSON 設定檔案，恢復所有設定
- **FR-071**: 設定檔案必須可跨平台移植（Windows、Linux、macOS）
- **FR-072**: 系統必須在設定變更後立即儲存到本地 JSON 檔案

#### 自動更新

- **FR-073**: 系統必須定期檢查應用程式更新（可配置檢查頻率）
- **FR-074**: 系統必須在偵測到新版本時通知使用者
- **FR-075**: 使用者必須能夠一鍵下載並安裝更新
- **FR-076**: 系統必須支援模組自動更新（從指定的模組倉庫）

#### 安全與隱私

- **FR-077**: 系統必須使用加密演算法儲存使用者憑證（帳號密碼）
- **FR-078**: 系統必須驗證 HTTPS 連線的憑證
- **FR-079**: 系統不得包含任何遙測或使用者追蹤功能
- **FR-080**: 系統必須在 UI 中明確顯示是否正在使用 Proxy，讓使用者了解網路流量走向

#### 跨平台相容性

- **FR-081**: 系統必須在 Windows、Linux、macOS 上提供一致的核心功能
- **FR-082**: 系統必須針對各平台優化系統整合（托盤圖示、通知、檔案對話框等）
- **FR-083**: 系統必須正確處理各平台的路徑格式（`\` vs `/`）和特殊字元限制

### Key Entities

- **DownloadTask（下載任務）**: 代表單一下載任務
  - 屬性：唯一 ID、URL、檔名、檔案路徑、檔案大小、狀態（pending/downloading/paused/completed/failed）、進度（0-100%）、當前速度、分段資訊、建立時間、完成時間、使用的 Proxy、分類標籤
  - 關聯：屬於一個 DownloadQueue

- **DownloadSegment（下載分段）**: 代表下載任務的單一分段
  - 屬性：分段 ID、起始位元組、結束位元組、狀態（pending/downloading/completed/failed）、已下載位元組數、分配的執行緒、使用的 Proxy
  - 關聯：屬於一個 DownloadTask

- **DownloadQueue（下載佇列）**: 管理所有下載任務的佇列
  - 屬性：待下載任務列表、進行中任務列表、已完成任務列表、失敗任務列表
  - 行為：加入任務、移除任務、調整順序、批次操作

- **ProxyInfo（Proxy 資訊）**: 代表單一 Proxy 伺服器
  - 屬性：IP 位址、埠號、類型（HTTP）、狀態（可用/失效）、回應時間、成功率、最後驗證時間
  - 關聯：屬於 ProxyPool

- **ProxyPool（Proxy 池）**: 管理所有 Proxy
  - 屬性：可用 Proxy 列表、失效 Proxy 列表、驗證中 Proxy 列表
  - 行為：批次驗證、分配 Proxy、標記失敗、標記成功、快取到檔案、從檔案載入

- **WebsiteModule（網站模組）**: 代表支援特定網站的模組
  - 屬性：模組 ID、名稱、版本、支援的域名列表
  - 行為：驗證 URL、解析下載連結、處理 CAPTCHA、處理登入、執行 JavaScript

- **ProxyListModule（Proxy List 模組）**: 代表 Proxy List 來源模組
  - 屬性：模組 ID、名稱、版本、來源 URL
  - 行為：抓取 Proxy 列表、解析列表

- **AppSettings（應用程式設定）**: 代表所有使用者設定
  - 屬性：預設下載目錄、語言、主題、剪貼簿監聽開關、同時下載數限制、執行緒數、分段大小、速度限制、自動重試設定、排程設定、分類設定
  - 行為：匯出為 JSON、從 JSON 匯入、驗證設定值

- **DownloadHistory（下載歷史）**: 記錄所有歷史下載
  - 屬性：下載任務列表（包含已刪除的任務）
  - 行為：查詢歷史、篩選、匯出

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 使用者可以在 10 秒內從貼上 URL 到開始下載（包含剪貼簿自動偵測的流程）
- **SC-002**: 多線程分段下載相比單線程下載速度提升至少 50%（在支援 Range Request 的伺服器上測試）
- **SC-003**: 系統支援至少 100 個並發下載任務而不出現明顯效能下降（CPU 使用率 < 80%，記憶體 < 2GB）
- **SC-004**: 斷點續傳成功率達到 95% 以上（在網路中斷後恢復的測試中）
- **SC-005**: Proxy 驗證準確率達到 90% 以上（驗證為可用的 Proxy 實際下載成功率 > 90%）
- **SC-006**: Proxy 失敗自動切換時間少於 5 秒（從偵測失敗到切換成功）
- **SC-007**: 網站模組成功解析支援網站的下載連結成功率達到 95% 以上
- **SC-008**: 應用程式啟動時間少於 3 秒（冷啟動，不含模組載入）
- **SC-009**: UI 響應時間少於 100ms（使用者點擊按鈕到 UI 更新）
- **SC-010**: 下載完成通知延遲少於 1 秒（從檔案寫入完成到通知顯示）
- **SC-011**: 語言切換立即生效（少於 500ms）
- **SC-012**: 主題切換立即生效（少於 300ms）
- **SC-013**: 設定匯出/匯入成功率 100%（所有設定正確保存和恢復）
- **SC-014**: 跨平台設定移植成功率 100%（Windows、Linux、macOS 間移植設定無錯誤）
- **SC-015**: 錯誤恢復率達到 80%（自動重試成功解決的錯誤佔所有錯誤的比例）
- **SC-016**: 使用者在第一次使用時能夠在 5 分鐘內完成基本下載任務（無需閱讀文件）
- **SC-017**: 模組載入成功率達到 95%（有效模組能夠正確載入）
- **SC-018**: Chrome 擴充套件連結傳送成功率達到 99%（從擴充套件到應用程式）
- **SC-019**: 記憶體使用穩定，長時間執行（24 小時）記憶體增長少於 100MB（避免記憶體洩漏）
- **SC-020**: 大檔案（> 10GB）下載成功率達到 90% 以上

## Assumptions

1. **網路環境**: 假設使用者具有穩定的網路連線，平均頻寬至少 10Mbps
2. **檔案伺服器**: 假設大部分目標伺服器支援 HTTP Range Request，不支援的情況下降級為單線程
3. **作業系統**: 假設目標作業系統版本為 Windows 10+、macOS 11+、Ubuntu 20.04+
4. **瀏覽器**: Chrome 瀏覽器整合僅支援 Chrome 90+ 版本
5. **Proxy 來源**: 假設使用者自行取得 Proxy list，系統不提供內建的 Proxy 來源
6. **網站支援**: 初期僅提供檔案分享網站（如 MediaFire、Mega）和直接下載連結的模組，其他網站需要社群貢獻
7. **CAPTCHA 處理**: 預設使用手動 CAPTCHA 解決方案（使用者輸入），不整合自動化 CAPTCHA 解決服務
8. **資料持久化**: 所有資料使用 JSON 檔案儲存，不使用資料庫，假設下載歷史記錄數量不會超過 10,000 筆
9. **授權**: 專案使用 MIT 授權，允許自由使用和修改
10. **語言支援**: 初期支援繁體中文、英文、日文，其他語言透過社群貢獻加入
11. **更新機制**: 假設使用者有網路連線可以檢查和下載更新
12. **模組安全**: 假設使用者信任載入的模組，系統不提供模組簽章驗證（可在未來版本加入）

## Dependencies

- **Tauri**: 用於跨平台桌面應用程式框架
- **React**: 前端 UI 框架
- **Material UI**: UI 元件庫
- **Jotai**: 狀態管理
- **react-i18next**: 國際化
- **Rust**: Tauri 後端開發語言
- **reqwest**: Rust HTTP 客戶端
- **tokio**: Rust 非同步執行時
- **Headless browser library**: 用於執行 JavaScript（例如 `headless_chrome` 或類似）
- **Chrome Native Messaging API**: 用於 Chrome 擴充套件與應用程式通訊
- **作業系統 API**: 用於系統托盤、通知、自動啟動等功能

## Out of Scope

以下功能明確不在當前版本範圍內：

1. **FTP/SFTP 支援**: 僅支援 HTTP/HTTPS
2. **Torrent 下載**: 不支援 BitTorrent 協定
3. **影片串流下載**: 不支援 HLS/DASH 等串流協定
4. **內建媒體播放器**: 僅下載檔案，不提供預覽或播放功能
5. **雲端同步**: 不提供跨裝置的下載佇列同步
6. **移動端應用**: 僅支援桌面平台（Windows、Linux、macOS）
7. **瀏覽器擴充套件多瀏覽器支援**: 僅支援 Chrome，不支援 Firefox、Safari、Edge 等（雖然 Edge 可能相容）
8. **SOCKS4/SOCKS5 Proxy**: 僅支援 HTTP Proxy
9. **VPN 整合**: 不提供內建 VPN 功能
10. **自動化 CAPTCHA 解決**: 不整合第三方 CAPTCHA 解決服務（如 2Captcha）
11. **付費訂閱**: 完全免費開源，無付費功能
12. **社交功能**: 不提供分享、評論、社群功能
13. **內建檔案管理器**: 不提供完整的檔案瀏覽和管理功能
14. **檔案轉換**: 不提供下載後的檔案格式轉換（例如影片轉碼）
15. **網路流量分析**: 不提供詳細的網路流量統計和分析儀表板
