# Feature Specification: 下載網站串接模組系統

**Feature Branch**: `004-site-module-integration`
**Created**: 2025-12-04
**Status**: Draft
**Input**: User description: "接下來我要實作特定下載網站的串接模組功能，其中包含模組的接口，以及實作一個模組並串接。第一個串接的模組是 k2s"

## Clarifications

### Session 2025-12-04

- Q: 關於「混合下載列表」的設計意圖 → A: 使用者不應關注下載連結所使用的模組，除非模組執行發生問題才回報。當使用者貼上連結後會自動解析網址並觸發對應的模組。模組應該透明運作，不需要在 UI 上顯示「K2S 模組」、「通用」等標記。
- Q: 是否需要模組管理功能 → A: 需要在設定頁面新增「網站模組管理」功能，顯示已安裝模組的資訊：模組名稱、版本、作者、描述、首頁連結。
- Q: 模組實作語言和認證安全 → A: 使用 JavaScript 實作模組（透過嵌入 deno_core），搭配認證代理機制確保安全。模組透過 manifest 檔案聲明所需權限和允許存取的網域，應用程式僅授予 manifest 中聲明的權限，防止模組濫用功能或連接不該連的網域。
- Q: 模組系統是否還有其他安全風險 → A: 識別出多項潛在安全風險（資料竊取、資源濫用、SSRF、沙箱逃逸等），需要實作全面的安全防護機制，包括：嚴格沙箱隔離、資源限制、輸出驗證、審計日誌、網路請求監控、內網保護。必須透過安全測試驗證這些防護機制的有效性。

## User Scenarios & Testing

### User Story 1 - 支援 Keep2Share (K2S) 下載 (Priority: P1)

使用者想要下載 Keep2Share (k2s.cc) 網站上的檔案。當使用者貼上 K2S 連結時，系統在背景自動識別並使用 K2S 專用模組來處理認證、連結解析和下載流程。整個過程對使用者是透明的，除非發生錯誤。

**Why this priority**: 這是第一個實作的網站模組，建立了整個模組系統的基礎架構。K2S 是常見的檔案分享網站，支援它能立即為使用者帶來價值，同時驗證模組系統的可行性。

**Independent Test**: 使用者提供一個有效的 K2S 連結，系統能完成完整的下載流程（識別、認證、解析、下載），無需依賴其他網站模組。使用者不需要手動選擇或指定模組。

**Acceptance Scenarios**:

1. **Given** 使用者已登入 K2S 帳號，**When** 使用者貼上一個 K2S 檔案連結，**Then** 系統自動識別並在背景使用 K2S 模組處理，使用者看到的是正常的下載流程
2. **Given** 系統識別出 K2S 連結，**When** 使用者點擊下載，**Then** 系統使用 K2S 模組取得真實下載連結並開始下載，過程對使用者透明
3. **Given** K2S 需要驗證碼，**When** 下載請求被觸發，**Then** 系統提示使用者輸入驗證碼並等待使用者回應後繼續
4. **Given** K2S 帳號未登入，**When** 使用者嘗試下載，**Then** 系統提示使用者提供 K2S 認證資訊
5. **Given** K2S 模組執行失敗，**When** 錯誤發生，**Then** 系統顯示明確的錯誤訊息，包含模組名稱和失敗原因

---

### User Story 2 - 可擴展的模組架構 (Priority: P1)

開發者或進階使用者希望能夠新增其他下載網站的支援。系統提供清晰的模組介面，讓新的網站支援可以透過實作標準介面來新增，而無需修改核心下載引擎。模組以 JavaScript 編寫，透過 manifest 聲明權限。

**Why this priority**: 模組化架構是此功能的核心價值。如果架構設計不當，後續新增網站支援會變得困難且容易導致系統不穩定。這個 story 確保系統具有可擴展性。

**Independent Test**: 可以獨立測試模組註冊、發現和呼叫機制。不需要完整實作所有網站模組，只需確認新模組能被正確載入和呼叫。

**Acceptance Scenarios**:

1. **Given** 系統啟動，**When** 載入模組，**Then** 所有已註冊的網站模組都能被系統發現和載入
2. **Given** 使用者貼上一個連結，**When** 系統檢查連結，**Then** 系統自動選擇對應的網站模組（或回退到通用下載），無需使用者介入
3. **Given** 某個網站模組發生錯誤，**When** 該模組執行失敗，**Then** 系統記錄錯誤並提供明確的錯誤訊息，不影響其他模組運作
4. **Given** 開發者實作新的網站模組，**When** 新模組符合標準介面並提供有效的 manifest，**Then** 系統能自動整合新模組而無需修改核心代碼
5. **Given** 模組嘗試存取未在 manifest 中聲明的網域，**When** 模組執行 HTTP 請求，**Then** 系統拒絕該請求並記錄權限違規

---

### User Story 3 - 管理網站模組認證資訊 (Priority: P2)

使用者需要為不同的下載網站提供認證資訊（帳號、密碼、API 金鑰等）。系統提供安全的方式儲存和管理這些認證資訊，並在需要時自動使用。認證資訊由主程式安全保管，模組永遠無法直接存取，只能透過認證代理 API 發送請求。

**Why this priority**: 認證管理是實用性的關鍵，但不影響核心架構。可以先用基本的認證方式（如環境變數或設定檔），後續再增強為更友善的 UI 管理介面。

**Independent Test**: 可以單獨測試認證資訊的儲存、讀取和使用流程，無需完成所有下載功能。

**Acceptance Scenarios**:

1. **Given** 使用者首次使用需要認證的網站模組，**When** 下載請求被觸發，**Then** 系統提示使用者輸入該網站的認證資訊
2. **Given** 使用者已儲存認證資訊，**When** 使用同一網站的模組下載檔案，**Then** 系統自動使用已儲存的認證資訊，無需再次輸入
3. **Given** 認證資訊已過期或無效，**When** 模組嘗試使用認證，**Then** 系統提示認證失敗並要求使用者更新認證資訊
4. **Given** 使用者想要修改或刪除認證資訊，**When** 使用者在設定中操作，**Then** 系統允許更新或移除特定網站的認證資訊
5. **Given** 模組嘗試直接存取認證資訊，**When** 模組呼叫未授權的 API，**Then** 系統拒絕存取並記錄安全違規

---

### User Story 4 - 網站模組管理介面 (Priority: P2)

使用者想要查看系統中已安裝的網站模組資訊。在設定頁面中提供「網站模組管理」功能，列出所有已載入的模組及其詳細資訊（名稱、版本、作者、描述、首頁連結）。同時顯示每個模組聲明的權限和允許存取的網域，讓使用者能檢視模組是否濫用權限。

**Why this priority**: 這是使用者了解系統能力和診斷問題的重要工具。雖然不是核心下載流程的一部分，但對透明度、安全性和可維護性很重要。可以在核心架構完成後實作。

**Independent Test**: 可以獨立測試模組資訊的顯示功能，不需要完整的下載流程。使用模擬的模組元資訊即可驗證 UI 顯示。

**Acceptance Scenarios**:

1. **Given** 系統已載入多個網站模組，**When** 使用者開啟設定頁面的「網站模組管理」區域，**Then** 顯示所有已安裝模組的列表
2. **Given** 模組列表顯示，**When** 使用者查看模組資訊，**Then** 每個模組顯示：模組名稱、版本號、作者、簡短描述
3. **Given** 使用者查看模組詳細資訊，**When** 點擊模組項目展開，**Then** 顯示該模組聲明的權限列表和允許存取的網域列表
4. **Given** 模組提供了首頁連結，**When** 使用者點擊連結，**Then** 在瀏覽器中開啟模組的首頁或文件頁面
5. **Given** 某個模組載入失敗，**When** 使用者查看模組列表，**Then** 該模組標記為「載入失敗」並顯示錯誤原因
6. **Given** 使用者檢視模組權限，**When** 發現模組聲明了不合理的權限（例如存取無關網域），**Then** 使用者能識別潛在的安全風險

---

### User Story 5 - 模組安全性驗證和測試 (Priority: P1)

系統必須確保模組無法竊取資料、濫用資源或攻擊系統。透過全面的安全測試驗證沙箱隔離、權限控制、資源限制和審計機制的有效性。

**Why this priority**: 安全性是模組系統的基礎，如果安全機制失效，整個系統將面臨嚴重風險。必須在模組系統上線前驗證所有安全防護的有效性。

**Independent Test**: 使用專門設計的惡意測試模組驗證安全機制，這些測試模組嘗試各種攻擊手法，系統必須成功阻止所有攻擊。

**Acceptance Scenarios**:

1. **Given** 測試模組嘗試存取未授權的網域，**When** 模組執行，**Then** 系統拒絕所有未授權請求，成功率 100%
2. **Given** 測試模組嘗試消耗大量資源（CPU/記憶體），**When** 超過限制，**Then** 系統強制終止模組執行並記錄事件
3. **Given** 測試模組嘗試存取危險的 JavaScript API（eval、Function constructor），**When** 模組執行，**Then** 系統阻止存取並拋出錯誤
4. **Given** 測試模組嘗試存取內網 IP（127.0.0.1、192.168.x.x），**When** 發送請求，**Then** 系統拒絕請求並記錄 SSRF 攻擊嘗試
5. **Given** 測試模組嘗試將下載 URL 發送到外部伺服器，**When** 檢測到可疑行為（短時間內多個不同網域請求），**Then** 系統標記並暫停模組
6. **Given** 測試模組嘗試直接存取認證資訊，**When** 呼叫未授權 API，**Then** 系統拒絕並記錄安全違規，認證資訊隔離成功率 100%
7. **Given** 測試模組嘗試污染全域物件（原型污染），**When** 模組執行，**Then** 沙箱隔離防止污染擴散到主程式
8. **Given** 測試模組進入無限迴圈，**When** 執行時間超過限制（5 秒），**Then** 系統強制終止並標記模組為不穩定
9. **Given** 所有安全測試完成，**When** 檢視審計日誌，**Then** 所有攻擊嘗試都被正確記錄，包含時間戳、模組 ID 和違規類型
10. **Given** 模組返回的下載 URL 包含內網 IP，**When** 系統驗證 URL，**Then** 系統拒絕並記錄可疑行為

### Edge Cases

#### 基本功能邊界情況

- **連結識別失敗**: 當系統無法確定連結屬於哪個網站模組時，回退到通用下載模式，使用者感知不到差異
- **模組衝突**: 當多個模組都聲稱支援同一個 URL 模式時，系統使用優先級規則自動選擇，或在無法確定時回退到通用下載
- **模組初始化失敗**: 當網站模組載入失敗時，系統記錄錯誤但不中斷整個應用，該網站的連結回退到通用下載，並在模組管理頁面標記為失敗
- **認證過期處理**: 在下載過程中認證 token 過期，系統嘗試自動重新認證或提示使用者重新登入
- **驗證碼處理**: K2S 或其他網站需要驗證碼時，系統暫停下載流程並等待使用者輸入，設定合理的逾時時間
- **網站規則變更**: 當目標網站更新 API 或規則導致模組失效時，系統能偵測並提供明確的錯誤訊息（包含模組名稱），建議使用者檢查模組更新
- **離線模式**: 當網站模組需要線上驗證但網路不穩定時，系統提供重試機制並記錄失敗原因
- **並行下載限制**: 某些網站限制同時下載數量，模組需要實作排隊機制以避免觸發限制
- **模組元資訊缺失**: 當模組未提供完整的元資訊時，系統使用預設值（如「未知作者」、「無描述」）並在管理頁面正常顯示
- **Manifest 格式錯誤**: 當模組的 manifest 檔案格式錯誤或缺失必要欄位時，系統拒絕載入該模組並在管理頁面顯示明確的錯誤訊息

#### 安全性邊界情況

- **權限違規**: 當模組嘗試執行超出 manifest 聲明的操作時（例如存取未授權的網域），系統拒絕該操作並記錄安全事件
- **網域白名單匹配**: 處理通配符模式（例如 `*.k2s.cc`）和子網域的匹配邏輯，確保模組只能存取明確允許的網域
- **認證代理繞過嘗試**: 當模組嘗試繞過認證代理直接存取網路時，系統阻止該行為並標記為惡意模組
- **沙箱逃逸嘗試**: 當模組嘗試存取被禁止的 JavaScript API（eval、Function、require、process 等）時，系統拒絕執行並標記為惡意模組
- **資源耗盡攻擊**: 當模組超過資源限制（CPU 時間、記憶體、堆積大小）時，系統強制終止模組執行並記錄事件
- **內網掃描 (SSRF)**: 當模組嘗試存取內網 IP（127.0.0.1、192.168.x.x、10.x.x.x、172.16-31.x.x）或本地服務時，系統拒絕請求並記錄安全事件
- **資料外洩檢測**: 當模組在短時間內（1 分鐘內）向多個不同網域（超過 3 個）發送請求時，系統標記為可疑行為並暫停模組
- **URL 驗證失敗**: 當模組返回的下載 URL 包含內網 IP、非 HTTP/HTTPS 協議或未授權網域時，系統拒絕並記錄可疑行為
- **原型污染攻擊**: 當模組嘗試污染 Object.prototype 或其他全域物件時，沙箱隔離防止污染擴散到主程式
- **無限迴圈**: 當模組執行時間超過限制（單次請求 5 秒）時，系統強制終止並標記模組為不穩定
- **記憶體洩漏檢測**: 當模組的記憶體使用持續增長且不釋放時，系統記錄警告並在超過限制時終止模組
- **請求頻率限制**: 當模組的請求頻率超過限制（每分鐘 60 個請求）時，系統限流並記錄異常行為
- **回應大小限制**: 當 HTTP 回應大小超過限制（10MB）時，系統中止下載並記錄異常
- **DNS Rebinding 防護**: 當偵測到 DNS 解析結果在短時間內變化（可能的 DNS rebinding 攻擊）時，系統拒絕請求
- **時間攻擊防護**: 系統不應洩露可用於時間攻擊的詳細錯誤訊息或時間差異資訊

## Requirements

### Functional Requirements

#### 核心模組系統

- **FR-001**: 系統必須提供標準的網站模組介面 (Module Interface)，定義模組需要實作的方法（URL 識別、連結解析、下載處理）
- **FR-002**: 系統必須能夠在啟動時自動發現和載入所有已註冊的網站模組
- **FR-003**: 網站模組必須以 JavaScript/TypeScript 編寫，由 Rust 後端透過嵌入式 JavaScript runtime (deno_core) 執行
- **FR-004**: 當連結無法被任何網站模組識別時，系統必須回退到通用下載模式
- **FR-005**: 系統必須能夠同時處理多個不同模組的下載任務而不互相干擾
- **FR-006**: 網站模組必須支援並行下載（多分段下載），遵循核心下載引擎的分段機制

#### Manifest 與權限系統

- **FR-007**: 每個網站模組必須提供 manifest 檔案（JSON 格式），聲明模組元資訊、所需權限和允許存取的網域
- **FR-008**: Manifest 必須包含：模組名稱、版本號、作者、描述、首頁連結（可選）、權限列表、網域白名單
- **FR-009**: 系統必須在載入模組前驗證 manifest 格式的正確性，格式錯誤則拒絕載入
- **FR-010**: 系統必須強制執行模組的權限限制，只允許模組執行 manifest 中聲明的操作
- **FR-011**: 系統必須強制執行網域白名單，模組只能存取 manifest 中聲明的網域（支援通配符如 `*.example.com`）
- **FR-012**: 當模組嘗試存取未授權的網域時，系統必須拒絕該請求並記錄權限違規事件

#### 認證安全與代理

- **FR-013**: 系統必須提供認證代理 API，模組透過此 API 發送需要認證的 HTTP 請求，模組永遠無法直接存取真實的認證資訊
- **FR-014**: 認證資訊（帳號、密碼、Token）必須由主程式安全儲存，使用作業系統提供的安全儲存機制（如 Keychain、Credential Manager）
- **FR-015**: 系統必須提供認證資訊管理功能，允許使用者儲存和管理不同網站的登入資訊
- **FR-016**: 當網站模組發生錯誤時，系統必須記錄詳細錯誤訊息並提供使用者友善的錯誤提示，錯誤訊息應包含模組名稱

#### K2S 模組實作

- **FR-017**: 系統必須實作 Keep2Share (K2S) 網站模組，支援 k2s.cc 網域的連結
- **FR-018**: K2S 模組必須能夠識別 K2S 連結格式（例如 `https://k2s.cc/file/[file_id]`）
- **FR-019**: K2S 模組必須處理 K2S 網站的認證流程，支援帳號密碼登入或 API 金鑰認證
- **FR-020**: K2S 模組必須能夠解析 K2S 分享連結並取得真實的下載 URL
- **FR-021**: K2S 模組必須處理 K2S 的驗證碼 (Captcha) 要求，提示使用者輸入驗證碼
- **FR-022**: K2S 模組必須支援付費會員和免費會員的不同下載規則（下載速度限制、等待時間等）

#### 模組管理介面

- **FR-023**: 系統必須在設定頁面提供「網站模組管理」區域，列出所有已載入的模組及其元資訊
- **FR-024**: 網站模組管理介面必須顯示每個模組的狀態（正常運作、載入失敗）和錯誤訊息（如果有）
- **FR-025**: 網站模組管理介面必須顯示每個模組聲明的權限列表和允許存取的網域列表
- **FR-026**: 下載任務必須內部記錄使用的模組名稱（用於錯誤報告和日誌），但不在正常的使用者介面上顯示

#### 安全性與沙箱

- **FR-027**: 系統必須在嚴格的沙箱環境中執行模組，限制可存取的 JavaScript API，禁止 eval、Function constructor、require、process、__proto__ 等危險功能
- **FR-028**: 系統必須限制單一模組的資源使用：CPU 時間 ≤ 5秒/請求、記憶體 ≤ 50MB、總堆積大小 ≤ 100MB
- **FR-029**: 系統必須驗證模組返回的所有 URL，拒絕內網 IP、非 HTTP/HTTPS 協議和未授權的網域
- **FR-030**: 系統必須記錄所有模組的網路請求、錯誤和安全違規到審計日誌（包含時間戳、模組 ID、行為類型、詳細資訊）
- **FR-031**: 系統必須限制模組的網路請求頻率（每分鐘最多 60 個請求）和回應大小（最大 10MB）
- **FR-032**: 系統必須偵測並阻止模組嘗試存取內網 IP（127.0.0.1、192.168.x.x、10.x.x.x、172.16-31.x.x、::1、fe80::等）或本地服務
- **FR-033**: 系統應在模組首次執行前向使用者顯示權限確認對話框，列出模組聲明的權限和網域（可選功能，可在設定中開啟）
- **FR-034**: 系統應支援程式碼簽章驗證，允許使用者選擇只信任已簽名的模組（未來功能）
- **FR-035**: 系統必須在偵測到模組可疑行為時（例如短時間內請求多個不同網域、超過請求頻率限制、多次權限違規）自動暫停該模組並通知使用者

### Key Entities

#### 核心實體

- **網站模組 (Site Module)**: 以 JavaScript 編寫的特定下載網站整合邏輯，包含 URL 識別規則、連結解析邏輯和下載處理流程
- **模組介面 (Module Interface)**: 標準化的 JavaScript API 定義，所有網站模組必須實作的函數和回調
- **模組 Manifest**: JSON 格式的模組配置檔案，聲明模組元資訊、所需權限和允許存取的網域
- **模組元資訊 (Module Metadata)**: 從 manifest 解析的模組描述性資訊，包含名稱、版本、作者、描述、首頁連結
- **模組權限 (Module Permissions)**: 模組在 manifest 中聲明的權限集合（例如 HTTP 請求、檔案存取等）
- **網域白名單 (Domain Whitelist)**: 模組在 manifest 中聲明的允許存取的網域列表，支援通配符模式
- **認證代理 (Credential Proxy)**: 主程式提供給模組的安全 API，讓模組能發送需要認證的請求而不暴露真實認證資訊
- **認證資訊 (Credentials)**: 由主程式安全儲存的認證資料，包含使用者名稱、密碼、API 金鑰、Token 等，與特定網站模組綁定
- **模組註冊表 (Module Registry)**: 管理所有已載入的網站模組，提供模組查詢、選擇和元資訊存取功能
- **下載任務 (Download Task)**: 擴展現有的 DownloadTask，新增模組識別資訊，記錄該任務使用的網站模組（僅用於內部記錄和錯誤報告）

#### 安全相關實體

- **模組沙箱 (Module Sandbox)**: 隔離的 JavaScript 執行環境，限制模組可存取的 API 和資源，防止惡意代碼影響主程式
- **資源限制器 (Resource Limiter)**: 監控和限制模組的資源使用（CPU、記憶體、執行時間），防止資源耗盡攻擊
- **審計日誌 (Audit Log)**: 記錄所有模組行為的日誌系統，包含網路請求、錯誤、安全違規、資源使用等
- **URL 驗證器 (URL Validator)**: 驗證模組返回的 URL 是否安全（協議、網域、IP 檢查），防止 SSRF 和資料洩漏
- **網路請求監控 (Network Monitor)**: 監控模組的網路請求模式，偵測異常行為（頻率異常、多網域請求、可疑目標）
- **安全事件記錄 (Security Event)**: 記錄安全相關事件（權限違規、攻擊嘗試、可疑行為）的結構化資料

## Success Criteria

### Measurable Outcomes

#### 功能性指標

- **SC-001**: 使用者能夠成功下載 K2S 網站上的檔案，完成率達 95% 以上（排除網站本身問題）
- **SC-002**: 從貼上 K2S 連結到開始下載的時間在 30 秒內（包含認證和連結解析時間）
- **SC-003**: 新增一個網站模組的開發時間不超過 4 小時（對熟悉系統的開發者）
- **SC-004**: 系統能同時處理至少 10 個不同模組的下載任務而不發生模組間干擾
- **SC-005**: 當網站模組發生錯誤時，90% 的錯誤訊息能明確指出問題原因（認證失敗、連結無效、網站不可用等）
- **SC-006**: 認證資訊儲存和讀取過程不超過 1 秒
- **SC-007**: K2S 模組能正確處理付費和免費帳號的差異，免費帳號的等待時間提示準確率達 100%
- **SC-008**: 模組系統的整體效能開銷不超過通用下載的 15%（CPU、記憶體使用，考慮 JavaScript runtime 開銷）
- **SC-009**: 模組管理頁面能在 1 秒內載入並顯示所有已安裝模組的資訊

#### 安全性指標

- **SC-010**: 權限違規檢測的準確率達 100%（所有未授權的網域存取都被成功阻止）
- **SC-011**: 模組永遠無法直接存取真實的認證資訊，認證代理的隔離成功率達 100%
- **SC-012**: 沙箱逃逸防護成功率達 100%（所有嘗試存取被禁止 API 的行為都被阻止）
- **SC-013**: 資源限制執行成功率達 100%（所有超過限制的模組都被正確終止）
- **SC-014**: 內網存取阻止成功率達 100%（所有嘗試存取內網 IP 的請求都被拒絕）
- **SC-015**: URL 驗證成功率達 100%（所有包含內網 IP 或非法協議的 URL 都被拒絕）
- **SC-016**: 審計日誌完整性達 100%（所有安全事件都被正確記錄，包含必要的上下文資訊）
- **SC-017**: 可疑行為偵測誤報率低於 5%（正常模組不會被誤判為可疑）
- **SC-018**: 安全測試套件涵蓋率達 100%（所有已知攻擊向量都有對應的測試案例）

## Assumptions

- 假設 K2S 網站的 API 或網頁結構相對穩定，或有參考實作可供借鑑
- 假設使用者願意提供必要的認證資訊（帳號密碼或 API 金鑰）
- 假設認證資訊儲存使用作業系統提供的安全儲存機制（如 Keychain、Credential Manager）
- 假設驗證碼處理採用人工輸入方式，不實作自動驗證碼識別
- 假設模組以 JavaScript/TypeScript 編寫，由 Rust 後端透過 deno_core 或類似的嵌入式 JavaScript runtime 執行
- 假設 JavaScript runtime 的嵌入會增加約 20-30MB 的應用程式大小，這是可接受的
- 假設每個網站模組包含一個 JavaScript 檔案和一個 manifest.json 檔案
- 假設 K2S 模組參考 https://github.com/lu8787ouo/k2s-Downloaderm 的實作邏輯（但以 JavaScript 重新實作）
- 假設模組 manifest 以靜態 JSON 檔案形式存在，不支援動態生成或修改
- 假設網域白名單支援基本的通配符模式（如 `*.example.com`），不需要複雜的正則表達式
- 假設模組無法繞過沙箱機制直接存取作業系統資源或網路，所有操作都必須透過主程式提供的 API
- 假設 deno_core 或選擇的 JavaScript runtime 提供足夠的沙箱隔離能力
- 假設審計日誌儲存在本地檔案系統，定期輪換以避免佔用過多空間
- 假設安全測試作為 CI/CD 流程的一部分自動執行，確保每次變更都不會破壞安全機制
